# 批量复用、工作恢复与性能验证（2026-10-07）

基于提交 `45e09fa`（PR #1）的后续改动。此记录为本地 Release 验证，不代表后续提交的 GitHub CI 已运行。

## 方法

使用 `scripts/PerformanceProbe` 在 WPF STA 线程和实际 DispatcherSynchronizationContext 下运行工作区模型。夹具包含 10 个文件、对白和共享字符串各一半，共 10,000 / 50,000 个逻辑翻译对象；包含空译文、正确占位符和缺失占位符。每个操作预热一次，再测量五次。

表中 P95 使用最近秩法，五次采样时等于最大值。界面间隔为 Dispatcher 每 10ms 的高优先级心跳实际最大间隔，包含线程调度与 GC，作为响应性代理指标；不等同于完整窗口绘制耗时。探针同时断言所有工作区属性通知均来自界面线程。实际 WPF 视图的宽窄布局与交互另行验证。

同机对比：基线使用 `45e09fa` 的独立源码副本，当前版本使用本分支；没有改动基线。测量过程不加载真实游戏或调用翻译接口。

## 结果

| 逻辑条目数 | 操作 | 基线总耗时 P95（ms） | 当前总耗时 P95（ms） | 基线最大界面间隔（ms） | 当前最大界面间隔（ms） |
| --- | --- | ---: | ---: | ---: | ---: |
| 10,000 | 搜索 | 0.5 | 219.1 | 0.5 | 34.6 |
| 10,000 | 文件范围切换 | 0.4 | 3.1 | 0.4 | 3.1 |
| 10,000 | 质量刷新 | 55.8 | 66.2 | 55.8 | 31.7 |
| 10,000 | 批量预览 | — | 21.4 | — | 15.3 |
| 50,000 | 搜索 | 2.4 | 218.2 | 2.4 | 32.8 |
| 50,000 | 文件范围切换 | 3.5 | 6.4 | 3.5 | 6.3 |

| 50,000 | 批量预览 | — | 138.3 | — | 34.4 |

当前搜索含主动设置的 200ms 输入防抖；扣除后 50,000 条的 P95 约 18.2ms。旧版搜索本身已经很快，新版引入后台调度和防抖是为了合并连续输入，而不是声称单次搜索更快。主要改善是质量检查的界面响应性。当前测量满足筛选 P95 小于 500ms（不含防抖）及最大界面间隔小于 100ms 的目标，但不构成所有硬件或真实项目的性能保证。

原始数据：[基线](performance-20261007-baseline.json)、[当前](performance-20261007-current.json)。

## 复现

在仓库根目录执行（Windows、.NET 10）：

```powershell
dotnet run --project scripts/PerformanceProbe -c Release -- E:/_codex_work/rls-performance-current.json
# 基线必须指向单独检出的源码目录，避免覆盖正在工作的分支。
dotnet run --project scripts/PerformanceProbe -c Release -p:StudioRoot=E:/_codex_work/rls-baseline-45e09fa -- E:/_codex_work/rls-performance-baseline.json
```

探针只在 `E:/_codex_work/rls-performance-fixture` 写入其设置文件；不写入真实翻译项目。性能检查独立于 CI，不加入易受机器负载影响的耗时断言。

## 功能验收

- 批量预览仅填空译文，按编辑对象去重；来源或目标变化阻止过期应用；多译法、冲突、复杂块和占位符异常正确跳过。
- 保存后撤销、再次编辑后阻止撤销、部分保存失败、自动保存及自动保存结构警告均有回归覆盖。
- 按项目与语言恢复筛选和书签，兼容旧设置；覆盖唯一上下文重新定位、失效书签、无效范围和隐藏的上次位置。
- 连续筛选、质量刷新期间编辑、切换语言、取消、关闭工作区和大型投影导航均有回归覆盖。
- 真实 WPF 视图以 640 / 1,000 像素渲染批量预览；通过真实复选框绑定验证排除条目、应用和撤销。主窗口同时复核 720 / 1,000 / 1,500 像素布局及原有快捷键。
