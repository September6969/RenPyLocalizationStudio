# ADR 0001：Project Snapshot 的会话编辑模型

- 状态：已采纳
- 日期：2026-08-30

## 背景

项目分析需要一次性建立流程图、Translation Binding、共享字符串和文件哈希基线。界面随后会持续编辑译文，并且一次保存可能只成功提交部分文件。把整个 Project Snapshot 描述成完全只读，会迫使应用在每次编辑或部分保存后重新分析，也无法准确表达已经提交与仍然脏的文件状态。

## 决策

Project Snapshot 采用“结构稳定、编辑状态可变”的会话模型：

- FlowGraph、源码区域和 Translation Binding 在下一次项目分析前保持结构稳定；
- TranslationUnit 与 SharedStringEntry 的译文和脏状态可在会话中更新；
- 每个 TL 文档独立维护预期哈希、编码信息和提交状态；
- 保存服务返回逐文件提交结果，只为实际原子替换成功的文件更新哈希基线；
- 外部文件变化、绑定结构变化或项目/语言切换仍要求重新分析。

## 后果

- 部分保存可以准确恢复到可继续编辑的状态，不会重复写入已成功文件；
- UI 覆盖率和脏状态可以增量更新；
- Core 服务必须避免把结构变更隐藏在译文编辑操作中；
- 新增会影响节点、绑定或源码区域的功能时，必须产生新的 Project Snapshot，而不是原地修改结构。
